# Design Document: ระบบหักล้างยอดข้ามงวด (Cross-Round Settlement Offset Wizard)

**Date:** 2026-09-10  
**Status:** Approved  
**Author:** Pair Programming Assistant & User  

---

## 1. บทนำและปัญหา (Overview & Problem Statement)

ในธุรกิจการรับ-ส่งหวยจริง สมาชิก (คนส่งเลข) และเจ้ามือ มักจะไม่ได้เคลียร์เงินแบบงวดต่องวด 100% เสมอไป ในหลายสถานการณ์สมาชิกอาจมีหนี้ค้างชำระจากงวดก่อนหน้า (เช่น งวด `16-8-69` ค้าง ฿4,000) และเมื่อเข้าสู่งวดใหม่ (เช่น งวด `1-9-69`) สมาชิกถูกรางวัล (เช่น ฿3,000)

ในทางปฏิบัติ เจ้ามือและสมาชิกจะตกลง **"หักล้างเงินรางวัลงวดใหม่กับหนี้งวดเก่า (Cross-round Offset)"** แล้วโอนเฉพาะส่วนต่างที่เหลือด้วยสลิปเดียว (เช่น ฿4,000 - ฿3,000 = โอนสลิป ฿1,000)

**ข้อจำกัดของระบบปัจจุบัน:**
* ระบบบันทึกการชำระเงินแยกอิสระตามแต่ละงวด (`round_id`)
* หากเจ้ามือถือสลิป ฿1,000 แล้วนำไปลงในงวดปัจจุบัน:
  * งวดเก่าจะยังคงขึ้นสถานะว่าค้างชำระ ฿4,000 เท่าเดิม
  * งวดปัจจุบันจะไม่ได้ตัดยอดเงินรางวัล ฿3,000 ออก ส่งผลให้ยอดคงเหลือผิดเพี้ยนทั้งสองงวด
* หากให้เจ้ามือสลับไปหน้างวดเก่าเพื่อลงรับชำระ ฿4,000 แล้วสลับกลับมางวดใหม่เพื่อลงจ่ายรางวัล ฿3,000 จะเป็นขั้นตอนที่ซับซ้อน เสียเวลา และจำสับสนง่าย

## 2. เป้าหมาย (Goals & Scope)

1. **ทำรายการจุดเดียวจบ (Single-Slip Entry):** เจ้ามือกรอกสลิปส่วนต่างเพียงครั้งเดียวจากงวดปัจจุบัน ระบบจะสร้าง Record ลงบัญชีให้ทั้งงวดเก่าและงวดปัจจุบันอัตโนมัติ
2. **ตรวจจับหนี้เก่าอัตโนมัติ (Smart Detection):** เมื่อเปิดดูสมาชิกที่มีเงินรางวัลในงวดปัจจุบัน ระบบจะตรวจสอบว่าสมาชิกคนนี้มีหนี้ค้างจากงวดก่อนหน้าหรือไม่ หากมีจะแสดงแถบแจ้งเตือนพร้อมปุ่มลัด
3. **เลือกงวดเก่าได้หลายงวด (Multi-Round Selection):** รองรับกรณีสมาชิกค้างหลายงวด โดยเจ้ามือสามารถติ๊กเลือกงวดเก่าที่ต้องการนำมาหักล้างได้ตามต้องการ
4. **รองรับทั้งสองทิศทาง (Bidirectional Offset):**
   * หนี้เก่า > รางวัลใหม่: สมาชิกโอนส่วนต่างมาให้เจ้ามือ
   * รางวัลใหม่ > หนี้เก่า: เจ้ามือโอนส่วนต่างคืนให้สมาชิก (หรือตัดหนี้เก่าแล้วเหลือค้างจ่ายรางวัล)
   * หนี้เก่า = รางวัลใหม่: เคลียร์ยอด ฿0 ได้ทันที
5. **อ้างอิงชัดเจน ตรวจสอบย้อนหลังได้ (Audit Trail):** ทุก Record ที่สร้างขึ้นจะบันทึกหมายเหตุระบุความเชื่อมโยงข้ามงวดอย่างชัดเจน
6. **ครอบคลุมทั้ง 2 ระบบ:** รองรับทั้ง **สมาชิก (Member Settlement)** และ **เจ้ามือรับตีออก (Upstream Settlement)**

## 3. สถาปัตยกรรมและหน้าจอผู้ใช้งาน (User Interface & UX Flow)

### 3.1 แถบแจ้งเตือนตรวจจับหนี้เก่า (Smart Detection Banner)
* **ตำแหน่ง:** แสดงอยู่ด้านบนของส่วนบันทึกชำระเงินใน `MemberSettlementInline` และ `UpstreamSettlementInline`
* **เงื่อนไขการแสดง:** แสดงเมื่อ
  1. งวดปัจจุบันสมาชิกมียอดถูกรางวัล (`totalWinnings > 0`)
  2. มีงวดก่อนหน้าที่สมาชิกคนนี้มียอดคงค้าง (`currentBalance > 0` ที่คนส่งค้างเจ้ามือ)
* **ดีไซน์:** แถบ Dark Glassmorphism กรอบสีฟ้า-ทองเรืองแสง พร้อมข้อความ:
  > ⚡ **ตรวจพบยอดค้างชำระจากงวดก่อนหน้า:** สมาชิกมียอดค้างรวม `฿X,XXX` จาก `N` งวด และมียอดถูกรางวัลงวดนี้ `฿Y,YYY`  
  > `[ ⚡ หักล้างยอดกับงวดเก่า (Cross-Round Offset) ]`

---

### 3.2 หน้าต่าง Wizard หักล้างยอด (CrossRoundOffsetModal)
เมื่อกดปุ่มเปิด Wizard จะแสดง Modal ที่มีขนาดกระชับ ไม่ล้นจอ พร้อมขั้นตอนคำนวณ 4 ส่วน:

#### ส่วนที่ 1: ข้อมูลสรุปงวดปัจจุบัน
* ชื่องวดปัจจุบัน (เช่น `01/09/2026`)
* ยอดเงินรางวัลที่สามารถนำไปหักล้างได้: `฿3,000`

#### ส่วนที่ 2: รายการงวดเก่าที่มีหนี้ค้าง (Past Rounds Checklist)
* ตารางรายการงวดเก่าที่ยังมียอดค้าง เรียงจากงวดเก่าสุดไปใหม่งวดล่าสุด
* แต่ละแถวมี **Checkbox** ให้เลือก:
  * วันที่งวด / ประเภทหวย
  * ยอดหนี้คงค้างของงวดนั้น
* มีตัวเลือก **"เลือกทั้งหมด" (Select All)**
* แสดงผลรวมหนี้ที่เลือก: `รวมหนี้เก่าที่เลือก: ฿4,000`

#### ส่วนที่ 3: กล่องสรุปผลต่างสุทธิ (Net Calculation Box)
* แสดงสมการคำนวณอัตโนมัติ:
  $$\text{หนี้เก่าที่เลือก } (฿4,000) - \text{รางวัลงวดนี้ } (฿3,000) = \text{ส่วนต่างสุทธิ } (฿1,000)$$
* แสดงสถานะ:
  * 🟢 **สมาชิกต้องโอนชำระเพิ่ม:** `฿1,000` (หากหนี้ > รางวัล)
  * 🔴 **เจ้ามือต้องโอนคืนสมาชิก:** `฿...` (หากรางวัล > หนี้)
  * ⚪ **หักล้างกันพอดี (ไม่ต้องโอน):** `฿0`

#### ส่วนที่ 4: ข้อมูลการชำระเงินจริง
* **จำนวนเงินตามสลิป (Amount):** ค่าเริ่มต้นเป็นยอดส่วนต่างสุทธิ (`฿1,000`) สามารถแก้ไขได้
* **วันที่ชำระ (Paid Date):** ค่าเริ่มต้นเป็นวันที่ปัจจุบัน พร้อมปุ่มลัด `[วันนี้]`
* **หมายเหตุ (Notes):** ระบบสร้างข้อความอ้างอิงให้อัตโนมัติ:
  `สลิปโอน ฿1,000 + หักล้างรางวัลจากงวด 01/09/2026 (฿3,000)`

#### ส่วนที่ 5: ปุ่มดำเนินการ (Sticky Footer)
* `[ ยกเลิก ]`
* `[ ⚡ ยืนยันบันทึกหักล้างยอด ]` (Disabled หากไม่ได้เลือกงวดเก่า หรือกำลังบันทึก)

## 4. โครงสร้างข้อมูลและอัลกอริทึมการกระจายยอด (Database & Allocation Logic)

### 4.1 ตารางฐานข้อมูล
ใช้ตารางเดิมโดยไม่ต้องสร้างตารางใหม่:
* `member_round_payments` (สำหรับสมาชิก)
* `upstream_round_payments` (สำหรับเจ้ามือรับตีออก)

### 4.2 การสร้าง Record (Batch Insert)

สมมุติตัวอย่าง: หนี้เก่า 16-8-69 = ฿4,000, รางวัล 1-9-69 = ฿3,000, สลิป = ฿1,000

#### 1) ฝั่งงวดปัจจุบัน (Round `1-9-69`)
```javascript
{
  dealer_id: user.id,
  user_id: member.user_id,
  round_id: currentRoundId,
  payment_type: 'prize_payout',
  direction: 'dealer_to_member',
  amount: 3000, // ยอดรางวัลที่นำไปหักล้าง
  paid_at: paidDate,
  notes: `หักล้างหนี้งวดเก่า (16/08/2026) ฿3,000 [สลิปโอนจริง ฿1,000]`,
  created_by: user.id
}
```
* **ผลลัพธ์:** ยอดถูกรางวัล ฿3,000 ถือว่าจ่ายครบเรียบร้อย ส่วนยอดขายส่ง ฿2,000 ของงวดนี้ยังคงค้างรอชำระตามปกติ

#### 2) ฝั่งงวดเก่า (Round `16-8-69`)
```javascript
{
  dealer_id: user.id,
  user_id: member.user_id,
  round_id: pastRoundId,
  payment_type: 'net_settlement',
  direction: 'member_to_dealer',
  amount: 4000, // ยอดหนี้ที่ได้รับการเคลียร์
  paid_at: paidDate,
  notes: `สลิปโอน ฿1,000 + หักล้างรางวัลจากงวด 01/09/2026 (฿3,000)`,
  created_by: user.id
}
```
* **ผลลัพธ์:** ยอดหนี้ค้าง ฿4,000 ปิดยอดเป็น ฿0 (ชำระครบแล้ว) ทันที

### 4.3 อัลกอริทึมกระจายยอดหลายงวด (Chronological Allocation Algorithm)
หากผู้ใช้ติ๊กเลือกหลายงวดเก่า (เช่น งวด A ค้าง ฿1,000, งวด B ค้าง ฿3,000):
1. นำงวดเก่าที่เลือกมาเรียงตามลำดับเวลา (`created_at` เก่าสุดไปใหม่สุด)
2. รวมวงเงินเคลียร์ทั้งหมด = `ยอดรางวัลที่หักล้าง + สลิปโอนจริง`
3. วนลูปตัดหนี้งวดเก่าทีละงวด:
   * งวด A: ได้รับจัดสรร ฿1,000 -> บันทึกเคลียร์ยอด ฿1,000 (ปิดยอดงวด A)
   * งวด B: ได้รับจัดสรร ฿3,000 -> บันทึกเคลียร์ยอด ฿3,000 (ปิดยอดงวด B)
4. งวดปัจจุบัน: บันทึกตัดยอดเงินรางวัลตามจำนวนที่นำไปหักจริง

## 5. การจัดการ React State & Real-time Update

เมื่อบันทึกสำเร็จ:
1. อัปเดต `historyDetails[currentRoundId].payments` ให้มีรายการใหม่
2. หากงวดเก่าที่ถูกตัดยอดถูกโหลดอยู่ในแคช `historyDetails[pastRoundId]` ให้อัปเดต `payments` ของงวดเก่านั้นด้วยทันที ทำให้เมื่อเจ้ามือคลี่ดูงวดเก่า ยอดคงค้างจะกลายเป็น ฿0 ทันทีโดยไม่ต้องโหลดใหม่
3. อัปเดต `settlementOverview` ยอดสรุปภาพรวม
4. แสดง Toast แจ้งเตือน: `"บันทึกหักล้างยอดข้ามงวดสำเร็จ (2 งวด)"`

## 6. แผนการตรวจสอบและทดสอบ (Verification Plan)

1. **Unit Tests (`memberSettlementCalculator.test.js`):**
   * ทดสอบฟังก์ชันคำนวณส่วนต่างข้ามงวด (หนี้เก่า > รางวัลใหม่, รางวัลใหม่ > หนี้เก่า, หนี้เก่า = รางวัลใหม่)
   * ทดสอบอัลกอริทึมกระจายยอดชำระหลายงวดตามลำดับเวลา (FIFO Allocation)
2. **Integration & Build Tests:**
   * ตรวจสอบว่า `npm.cmd test` ผ่านครบ 100%
   * ตรวจสอบว่า `npm.cmd run build` ผ่าน 0 errors
3. **Manual Verification Flows:**
   * ทดสอบสมาชิกที่มีหนี้เก่างวดเดียว + รางวัลใหม่
   * ทดสอบสมาชิกที่มีหนี้เก่าหลายงวด + รางวัลใหม่
   * ตรวจสอบประวัติการชำระเงินของทั้งสองงวดว่ามีปุ่มแก้ไข/ลบ และแสดงหมายเหตุครบถ้วน
